## The short version

My background is in **finance, accounting and financial markets**. I did not start by learning technology for its own sake. I started with operating problems: fragmented spreadsheets, repetitive workflows, market data, trade accounting, strategy research and processes that needed to become reliable and repeatable.

That progression took me from **Excel → Python → APIs → databases → web/mobile products → cloud infrastructure → applied AI**.

Today I build H&L Software: a connected product ecosystem where the domain logic lives in backend services and multiple clients consume stable APIs.

> **Problem → Process → Data → Logic → Automation**

## What differentiates my work

**Domain before code.** I understand the financial workflow first: what the number means, where it comes from, what can go wrong and what decision depends on it.

**End-to-end ownership.** I work from requirement mapping and data design through backend logic, UI, integrations, deployment and operational debugging.

**Process-driven engineering.** I prefer explicit rules, observable workflows and repeatable execution over opaque automation.

**AI as an engineering tool.** I use AI to accelerate implementation and extraction workflows, while keeping deterministic financial/business validation in code where correctness matters.

**Built from real operating requirements.** The projects above grew from trading, accounting and workflow problems I actually needed to solve.
